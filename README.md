# BL

Backend services for a sports betting app. The repo contains the FastAPI API, data ingestion from a sports odds provider, and GCP infrastructure (Cloud Run + Neon Postgres) managed with Terraform. Auth is AWS Cognito.

## Highlights

- **FastAPI + PostgreSQL** for the core API and data model
- **Odds & fixtures ingestion** via RapidAPI (API-Football)
- **Bet settlement jobs** exposed via an admin UI
- **AWS Cognito auth** for client-facing endpoints
- **Infrastructure-as-code** with Terraform and CI/CD via GitHub Actions

## Deployment

Runs on **GCP** (Cloud Run + Neon Postgres), provisioned by Terraform via GitHub Actions (`gcp-deploy.yml`). CI authenticates to GCP **keyless via Workload Identity Federation** — the WIF pool + Terraform state bucket are bootstrapped once in the sibling `tf_bootstrap` repo. **AWS Cognito** stays for auth (its own stack, `terraform/cognito/`).

### Prerequisites
- A GCP project with billing, and the `tf_bootstrap` GCP bootstrap applied (state bucket + WIF).
- Terraform >= 1.5.
- A Neon account (the Neon project itself is created by Terraform via the Neon provider).

### GitHub Secrets Required
- `RAPID_API_KEY`, `OPENAI_API_KEY`, `ADMIN_SESSION_SECRET` — app secrets.
- `ADMIN_PASSWORD` — permanent password for the Cognito admin user (≥12 chars, upper/lower/number/symbol, or the Cognito apply fails opaquely).
- `NEON_API_KEY` — Terraform provisions the Neon project.
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` — Cognito stays on AWS: used to read the Cognito stack's remote state and for the app's boto3 admin calls.
- `VERCEL_API_TOKEN`, `VERCEL_PROJECT_ID`, `VERCEL_DEPLOY_HOOK_URL` — Terraform sets the FE's env vars and triggers the rebuild.

Admin login is Cognito-native. The Cognito pool + admin user are provisioned by Terraform (`terraform/cognito/`) and the Neon DB credentials are generated by Terraform, so no DB or Google-OAuth secrets are needed.

The GCP deploy propagates the Cognito ids + the **Cloud Run** API URL into the Vercel frontend project (as `NEXT_PUBLIC_*` env vars) via the `vercel` provider, then triggers a rebuild via the deploy hook — so the frontend is re-wired automatically on every redeploy, nothing pasted by hand. The Vercel project is referenced by ID, never created/destroyed by Terraform.

### Branches
- Push to `dev` → deploys the dev environment.
- `prod` (`terraform/gcp/prod`) is scaffolded but not yet wired for deploy.

The retired AWS App Runner + RDS stack is archived under `terraform/aws/` (reference only). Full migration record: `terraform/GCP_MIGRATION.md`.
