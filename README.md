# BL

Backend services for a sports betting app. The repo contains the FastAPI API, data ingestion from a sports odds provider, and GCP infrastructure (Cloud Run + Neon Postgres) managed with Terraform. Auth is GCP Identity Platform (Firebase Auth).

## Highlights

- **FastAPI + PostgreSQL** for the core API and data model
- **Odds & fixtures ingestion** via RapidAPI (API-Football)
- **Bet settlement jobs** exposed via an admin UI
- **GCP Identity Platform (Firebase Auth)** for client-facing endpoints; the Firebase Auth emulator for local dev
- **Infrastructure-as-code** with Terraform and CI/CD via GitHub Actions

## Deployment

Runs on **GCP** (Cloud Run + Neon Postgres), provisioned by Terraform via GitHub Actions (`gcp-deploy.yml`). CI authenticates to GCP **keyless via Workload Identity Federation** — the WIF pool + Terraform state bucket are bootstrapped once in the sibling `tf_bootstrap` repo. Auth is **GCP Identity Platform (Firebase Auth)**, provisioned by the `terraform/modules/identity-platform` module.

### Prerequisites
- A GCP project with billing, and the `tf_bootstrap` GCP bootstrap applied (state bucket + WIF).
- Terraform >= 1.5.
- A Neon account (the Neon project itself is created by Terraform via the Neon provider).

### GitHub Secrets Required
- `RAPID_API_KEY`, `OPENAI_API_KEY`, `ADMIN_SESSION_SECRET` — app secrets.
- `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` — Google OAuth Web client (created by hand in the console); backs both the end-user Google IdP and the admin panel OIDC login.
- `NEON_API_KEY` — Terraform provisions the Neon project.
- `VERCEL_API_TOKEN`, `VERCEL_PROJECT_ID`, `VERCEL_DEPLOY_HOOK_URL` — Terraform sets the FE's env vars and triggers the rebuild.

Admin login is Google OIDC — the admin gate is the token email matching `ADMIN_EMAIL` with a verified email. The Neon DB credentials are generated by Terraform.

The GCP deploy propagates the three `NEXT_PUBLIC_FIREBASE_*` values (apiKey from the Identity Platform config, authDomain `brokelads.co.uk`, projectId) + the **Cloud Run** API URL into the Vercel frontend project via the `vercel` provider, then triggers a rebuild via the deploy hook — so the frontend is re-wired automatically on every redeploy, nothing pasted by hand. The Vercel project is referenced by ID, never created/destroyed by Terraform.

### Branches
- Push to `dev` → deploys the dev environment.
- `prod` (`terraform/gcp/prod`) is scaffolded but not yet wired for deploy.

The retired AWS App Runner + RDS + Cognito stacks are archived under `terraform/aws/` (reference only); tear the Cognito pools down with the manual `cognito-teardown.yml` workflow after cloud verification. Full migration record: `terraform/GCP_MIGRATION.md`.
